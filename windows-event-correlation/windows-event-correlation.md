# ProcessGuid Correlation

## Scenario

### Sysmon Event ID 1

| Field | Value |
|--------|-------|
| Image | WINWORD.EXE |
| ProcessGuid | {81f71304-fb9b-6a54-1c05-000000003c00} |
| User | DESKTOP-LOIBRPI\VOSTRO |

---

### Sysmon Event ID 3

| Field | Value |
|--------|-------|
| Image | WINWORD.EXE |
| ProcessGuid | {81f71304-fb9b-6a54-1c05-000000003c00} |
| Destination IP | 150.171.110.147 |

---

## Analysis

Although the events occurred close in time, timestamps alone are not enough to confidently determine they belong to the same execution.

The shared `ProcessGuid` confirms that both events were generated by the same process instance.

---

## Key Lesson

Use **ProcessGuid** whenever possible to correlate Sysmon events instead of relying solely on timestamps.

# Hypothesis

## Hypothesis 1

A user authenticated remotely, executed PowerShell with the `-NoProfile` option, and established a connection to an internal host as part of an administrative workflow.

## Hypothesis 2

The observed sequence may represent suspicious activity, but the available evidence is insufficient to determine malicious intent.

The Notepad process and Windows Update service cannot currently be linked to the same process chain.

---

# Evidence Supporting

- Remote logon was observed.
- PowerShell was executed.
- The same PowerShell process established a network connection.
- The session received special privileges.

---

# Evidence Against

- `-NoProfile` is commonly used by administrators.
- The destination IP is within a private network.
- Notepad may be unrelated.
- Windows Update activity may be independent system behavior.

---

# Confidence Level

Low to Medium

The observed behavior is interesting but requires additional context before it can be classified as malicious.

---

# Additional Evidence Required

- Destination host role
- PowerShell command history
- Source IP of the RDP session
- User's normal behavior
- Additional Sysmon events linked by ProcessGuid

# Detection Observations

## Candidate Event 1

```text
PowerShell -NoProfile
```

### Assessment

Medium Detection Value

This command-line option is commonly used by administrators to launch a clean PowerShell session.

By itself, it should not generate a high-confidence alert.

# Lessons Learned

## 1. Correlation Is Essential

A single event rarely explains what happened.

Connecting events across multiple log sources provides a more complete picture.

---

## 2. ProcessGuid Is More Reliable Than Time

Multiple events may occur within the same second.

ProcessGuid uniquely identifies a specific process instance and enables accurate event correlation.

---

## 3. Context Reduces False Positives

Events such as:

- PowerShell -NoProfile
- Special Privileges Assigned
- Internal Network Connections

may all be legitimate depending on the environment.

---

## 4. Evidence Before Conclusions

Avoid assuming malicious activity based on a single indicator.

Gather supporting evidence before escalating an incident.

---

## 5. Think Across Logs

Security Log answers:

> Who authenticated?

Sysmon answers:

> What processes were executed?

Together, they allow analysts to reconstruct user behavior.
