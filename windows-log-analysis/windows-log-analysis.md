# Sample: Event ID 5379 Analysis

## Event Summary

| Field | Value |
|--------|-------|
| Event ID | 5379 |
| Provider | Microsoft Windows Security Auditing |
| Level | Information |
| Time Created | 2026-06-30 20:50:32 |
| User | N/A |
| Computer | DESKTOP-LOIBRPI |

---

## Description

Credential Manager credentials were read.

---

## Important Fields

| Field | Value |
|--------|-------|
| SubjectUserName | VOSTRO |
| SubjectDomainName | DESKTOP-LOIBRPI |
| TargetName | WindowsLive:(cert):name=disectioenist@gmail.com |
| ClientProcessId | 5148 |
| ProcessCreationTime | 2026-06-30T17:08:33Z |

---

## Initial Analysis

The event indicates that a process accessed credentials stored in Windows Credential Manager.

This event alone does **not** indicate malicious activity.

Additional context is required, including:

- Which process accessed the credentials
- Whether the activity matches the user's normal behavior
- Whether other suspicious events occurred around the same time

---

## Detection Value

Medium

This event becomes more valuable when correlated with:

- Process Creation (Sysmon Event ID 1)
- Logon Events (4624)
- Network Connections (Sysmon Event ID 3)

---

## Conclusion

Event ID 5379 should not be treated as malicious by itself.

Instead, it should be analyzed together with surrounding events to determine whether credential access was expected or suspicious.
